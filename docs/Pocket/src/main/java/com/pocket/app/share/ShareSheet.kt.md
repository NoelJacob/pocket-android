# Pocket/src/main/java/com/pocket/app/share/ShareSheet.kt
## What this is — the helper that opens the Android system share sheet for an article. It builds the `ACTION_SEND` text intent (quote plus share link), excludes Pocket's own "Add to Pocket" entry so users do not share back into the app, and sends browsers the original article URL instead of the Pocket share link. The `ShareReceiver` broadcast receiver exists to learn which app the user picked.
## How it fits — called at the end of the share flow by `ShareDialogFragment` after the share link is ready. It fires `Intent.createChooser` (the framework's app-picker dialog) with a `PendingIntent` callback (a token that lets the system notify us later) pointing at `ShareReceiver`, plus per-app replacement extras (alternate text for specific target apps) for known browsers. `ShareReceiver` is Hilt-injected (`AndroidEntryPoint` = Hilt provides its fields) and reads the chosen component (which app was tapped) from the callback intent.
## Key pieces — `ShareSheet.show(context, url, shareLink, quote, title)`: composes the text (`"quote"\n\nlink` or just the link), sets title, adds multi-task flags, attaches the chooser callback, and starts it; WHY: this is the single funnel so every share in the app behaves identically. `excludeOurShareExtension`: adds `EXTRA_EXCLUDE_COMPONENTS` for the Add-activity alias on Android N+; WHY: sharing into Pocket from Pocket is nonsense, and the alias (not the real class name) is what the manifest exposes. `sendOriginalUrlToBrowsers` + `replaceShareText`: maps ~25 browser package names to the raw article URL via `EXTRA_REPLACEMENT_EXTRAS`; WHY: opening a Pocket share-link wrapper inside a browser adds a useless redirect hop. `ShareReceiver.onReceive`: extracts `EXTRA_CHOSEN_COMPONENT` (the tapped app) from the callback; WHY: the seam for per-target share analytics.
## Junior notes — `EXTRA_REPLACEMENT_EXTRAS` only works with `createChooser` + a callback `IntentSender` — dropping the `PendingIntent` would silently disable the browser-URL substitution. The browser package list is a hardcoded allowlist from a 10-browser report; a new browser just falls back to the share link, which still works. `ShareReceiver`'s body is currently a stub (reads the component, does nothing) — that is intentional scaffolding for future logging, not dead code to delete.
