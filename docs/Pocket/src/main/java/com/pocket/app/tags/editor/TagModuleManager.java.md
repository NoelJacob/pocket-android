# Pocket/src/main/java/com/pocket/app/tags/editor/TagModuleManager.java
## What this is — the brain of the tag editor: it owns the selected-tag list, validates new tags, keeps every editor section in sync, gates the loading spinner until all sections plus the owned-tag fetch finish, and counts analytics events (how tags were added). Sections never talk to each other directly — they call `addTag`/`removeTag`/`onTagInputTextChanged` here, and this fans the change out to everyone else.
## How it fits — created by `ItemsTaggingFragment` with the fragment as `TagModuleManagerListener` (loading/error/modified callbacks that drive the spinner, snackbar, and save-button state). The fragment registers each `TagModule` via `addTagModule`, then calls `load(preselected)`; on save it reads `getListForReadOnly()`. The save button's enabled state binds to this manager as a `ViewEnabledCondition` (an "is it OK to enable" predicate), and instance state round-trips through `onSaveInstanceState` so rotation preserves selections.
## Key pieces — `load(selected)`: sets `mLoadingCount = modules + 1`, calls each module's `load(this)`, and syncs the owned `tags` thing; on success seeds selections and broadcasts `onTagsLoaded`, counting down to `onAllModulesLoaded`; WHY: one gate guarantees the screen appears only when every section is ready. `addTag(from, tag)`: validates first (reserved `_untagged_`, 25-char max) showing the manager error on failure, else appends and notifies all modules except the originator, then marks modified; WHY: the skip-originator fan-out prevents echo loops. `removeTag(from, tag)` / `onTagInputTextChanged(from, text)`: same fan-out pattern for removals (also counting chip-deletes) and keystrokes; WHY: one consistent broadcast rule for all three event types. `onModified()` (ignored while loading) + `isModified()` + `isEnabled()`: the dirty flag that enables Save; WHY: loading-time seeding must not mark the form dirty. `containsTag` (case-insensitive over all owned tags): backs the add-new row's hide rule; WHY: prevents duplicate tags differing only by case. Analytics counters (`mContextOpenTagsCount`, `Enter`, `SuggestedAdd`, `Tap`, `Removed`): classified by which module type added the tag (filtered-list picks count as entered, unfiltered as tapped); WHY: measures which discovery path users actually use. `premiumSubscription`: re-notifies modules on login/premium change after load; WHY: suggestions visibility can flip mid-session.
## Junior notes — `getListForReadOnly()` returns the live list — the "read only" is a promise you must keep; the fragment sorts it in place at save, which mutates manager state, so do not rely on its order beforehand. `onDestroy()` stops the premium subscription; skipping it leaks the fragment. The `MUTLI_ITEM` typo in the fragment's enum is real — search for that spelling when grepping.
