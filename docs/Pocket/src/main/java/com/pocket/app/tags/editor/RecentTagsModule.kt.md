# Pocket/src/main/java/com/pocket/app/tags/editor/RecentTagsModule.kt
## What this is — the "recent tags" strip in the tag editor showing up to three tappable recent tags. Tapping one adds it to the current selection and removes it from the strip. The strip hides while the user is typing and when there are no recents left. Data comes from the sync engine's `Tags.recentlyUsed` list.
## How it fits — a `TagModule` plug-in registered in `ItemsTaggingFragment.onCreateModules`, inflated from `ViewRecentTagsModuleBinding` (databinding = an XML layout with generated field accessors, here `tag1/tag2/tag3` plus dividers). `TagModuleManager.load()` triggers `load()`; keystrokes arrive via `onTagInputTextChanged`; taps go back out through `manager.addTag()` so chips, list, and suggestions update together.
## Key pieces — `load(callback)`: syncs the `tags` thing, copies `recentlyUsed` tag names into `recentTags`, refreshes the three slots, then reports loaded — throwing a `RuntimeException` on failure; WHY: recents are server-ordered data, not locally computed. `views.update()`: sets visibility by non-emptiness, fills each slot with `setTextOrHide` (helper that hides the view when the value is null), and mirrors divider visibility to its tag; WHY: one method keeps text, slots, and dividers consistent. `setTagAddingClickListener`: on tap, adds through the manager and calls `onTagAdded` to drop it from the strip; WHY: self-removal keeps the strip from offering an already-selected tag. `onTagInputTextChanged` / `onTagAdded`: hide while typing; remove added tags from the backing list and refresh; WHY: typing means the user is creating, not picking. `onTagRemoved`: intentionally does nothing; WHY: un-selecting a recent does not re-suggest it.
## Junior notes — Only three slots exist — `getOrNull(0..2)` silently drops older recents, which is by design, not a truncation bug. The `RuntimeException` on sync failure will crash the editor load; that fail-fast choice is in the source, so a flaky-recents crash points here first. `manager` here is the Java `getManager()` exposed to Kotlin as a property — same object.
