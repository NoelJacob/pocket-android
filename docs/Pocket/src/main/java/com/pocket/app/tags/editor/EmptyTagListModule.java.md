# Pocket/src/main/java/com/pocket/app/tags/editor/EmptyTagListModule.java
## What this is — the empty-state illustration for the tag editor ("you have no tags yet"). It shows only when the user owns zero tags AND is not currently typing; as soon as any tag exists or any input appears, it hides. It never modifies tags itself.
## How it fits — registered alongside the other `TagModule` sections in `ItemsTaggingFragment.onCreateModules` and coordinated by `TagModuleManager`. The manager delivers the full tag list once via `onTagsLoaded` and every keystroke via `onTagInputTextChanged`; this module combines those two booleans into one visibility decision surfaced through `setPreferredVisibility`, which the adapter turns into show/hide.
## Key pieces — `onTagsLoaded(allTags)`: records `mIsTagsEmpty = allTags.isEmpty()` and refreshes; WHY: the "owns no tags" half of the condition arrives asynchronously after load. `onTagInputTextChanged(text)`: records `mHasInput = !empty` and refreshes; WHY: typing means the add-new row takes over, so the illustration must yield. `updateVisibility()`: `setPreferredVisibility(mIsTagsEmpty && !mHasInput)`; WHY: the AND is the whole rule — either condition alone hides it. `load(callback)`: immediately reports loaded; WHY: no async work, but must still count down the manager's load gate.
## Junior notes — `TagModule.setPreferredVisibility` is a request, not a command — the parent adapter decides placement, so never assume `getView()` visibility equals your preference. The empty `onTagAdded`/`onTagRemoved` overrides are required by the base class but correctly do nothing here; selection changes cannot affect emptiness of the owned-tag set.
