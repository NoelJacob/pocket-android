# Pocket/src/main/java/com/pocket/app/tags/editor/TagListModule.java
## What this is — the "all tags" list in the tag editor: every unselected tag the user owns, tappable to select. While the user types it filters to tags starting with the input (autocomplete mode); with empty input it shows everything. It renders its rows through the fragment's adapter rather than owning a view — note `getView()` returns null by design.
## How it fits — registered in `ItemsTaggingFragment.addTagListModule` with the sticky-header views; its visibility callback drives both the in-list header and the pinned copy plus the adapter's tag rows (`adapter.setTags(getDisplayList())`). `TagModuleManager` feeds it the full tag set via `onTagsLoaded` and every keystroke via `onTagInputTextChanged`; row taps arrive as `onClick` and go back out through the manager's add path. Selection changes anywhere trigger `onTagAdded`/`onTagRemoved`, which just re-run the filter so picked tags drop out of the list.
## Key pieces — `mSourceList` (all tags) vs `mDisplayList` (filtered, actually shown): the two-list split; WHY: filtering never destroys the source, so clearing the input restores instantly. `TagFilter` (an Android `Filter`, a helper that runs matching off the UI thread): prefix-matches against the constraint, then updates the display list and visibility; WHY: keeps typing smooth over large tag sets. `onTagInputTextChanged(text)`: stores the constraint and re-filters; WHY: every keystroke narrows the offered tags. `updateVisibility()` (`mIsFiltered || !mSourceList.isEmpty()`): visible when filtering or when any tags exist; WHY: an empty unfiltered list collapses so the empty-state module can show. `onClick(v)`: resolves the tapped row's tag and adds it through the manager; WHY: list taps follow the same validated path as chips and suggestions. `setIsFiltered(boolean)`: tracks whether the constraint is non-empty; WHY: feeds the analytics distinction between typed-picks and tapped-picks.
## Junior notes — `getView()` returning null is not a bug — this module contributes rows to the shared `RecyclerView`, not a standalone section view; do not try to inflate one. `refilter()` after every add/remove is what removes selected tags from the offered list — if a picked tag still shows, the filter did not re-run. Matching is prefix-based and case-insensitive; substring matches intentionally do not appear.
