# Pocket/src/main/java/com/pocket/app/share/CreateShareLinkDialog.kt
## What this is — the share entry point used across the app: it shows a loading dialog, asks the server to wrap the article URL in a Pocket share link, then opens the Android system share sheet with that link (plus an optional quote and title). If link creation fails it silently falls back to sharing the original URL. It is two classes: `ShareDialogFragment` (the UI) and `CreateShareLinkDialogViewModel` (the logic).
## How it fits — callers never build the system share intent themselves; they call `ShareDialogFragment.show(fragmentManager, url/quote/title)` or the `DomainItem` overload (a `DomainItem` is the app's clean article model with `idUrl` and `displayTitle`), which opens this dialog. The dialog's `onCreateDialog` triggers `viewModel.onShown(url)`; the ViewModel (a lifecycle-aware holder that survives screen rotation; provided by Hilt DI, which supplies constructor params automatically) calls `ShareRepository.createShareLink()`, then emits `ShowShareSheet` and `Dismiss` events (one-shot happenings carried by a `SharedFlow`, an observable stream that emits to collectors). The fragment collects those events and forwards to `ShareSheet.show()`.
## Key pieces — `ShareDialogFragment.onCreateDialog`: launches a `lifecycleScope` coroutine (a background task tied to the fragment's lifetime) with `repeatOnLifecycle(RESUMED)` (only collect while the dialog is actually showing) that starts the link request; WHY: avoids firing the request when the dialog is not visible. `setupEventListener()`: collects `viewModel.events` and opens the share sheet or dismisses; WHY: keeps navigation in the UI layer, network in the ViewModel. `CreateShareLinkDialogViewModel.onShown(url)`: runs the repository call in `viewModelScope` (a coroutine scope that cancels when the ViewModel dies), falls back to the raw URL on any error, and emits both events; WHY: sharing must never fail just because link-wrapping did. `Event` sealed class (`ShowShareSheet` with original + share URLs, `Dismiss`): the complete UI contract; WHY: two states, no ambiguity. Companion `show`/`newInstance` overloads: accept either raw strings or a `DomainItem`; WHY: callers in list vs reader contexts have different data at hand.
## Junior notes — `ProgressDialog` is a deprecated Android dialog — it is intentionally still used here as a bare spinner with no customization planned. The double-emit (`ShowShareSheet` then `Dismiss`) is deliberate ordering: the sheet opens first, then the spinner goes away. `extraBufferCapacity = 1` on the event flow means emits never suspend even if the collector is briefly busy.
