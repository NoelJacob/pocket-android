# Pocket/src/main/java/com/pocket/app/settings/view/preferences/ActionPreference.java
## What this is — a tappable settings row with a title and an optional subtitle. Tapping it runs a callback (`OnClickAction`), and it can show different subtitles depending on whether the row is enabled. It is the base class for most other settings rows. The constructor is deprecated — new code should use the `PreferenceViews` builder helpers instead.
## How it fits — settings fragments (subclasses of `AbsPrefsFragment`, the base class for each Settings screen) build lists of `Preference` objects, and the fragment's adapter (the object that turns each `Preference` into a visible row and recycles those rows while scrolling) calls `getType()` to pick a layout, `applyToView()` to fill it in, and `onClick()` when tapped. `MultipleChoicePreference`, `RingtonePreference`, and `TtsEnginePreference` all extend this class and inherit its label/summary/click plumbing.
## Key pieces — `label` + `summary` (`SparseArray`, Android's memory-efficient map from int keys to objects) with keys `SUMMARY_UNAVAILABLE` / `SUMMARY_DEFAULT_OR_UNCHECKED` / `SUMMARY_CHECKED`: the three subtitle variants; WHY: one row can explain its disabled state without extra code. `getSummary()`: picks the enabled vs disabled subtitle, falling back to the default text; WHY: centralizes the "what does the user read" decision. `onClick(view)` / `onLongClick(v)`: forward to `action` / `longPressAction` if present; WHY: the row itself holds no behavior, only delegates. `isEnabled()` / `isClickable()`: clickable requires an action; enabled additionally requires the `EnabledCondition` (a small "should this row be greyed out" predicate) to pass; WHY: greying out and untappable are decided in one place. `applyToView(layout)`: binds title/subtitle into a `SettingsSwitchView` with the toggle hidden; WHY: all action rows share one visual style.
## Junior notes — `applyToView` receives a recycled row view, so it must set every field (title, subtitle, toggle visibility) each time — leftover state from a previous row is a classic bug. `update()` always returns false here, meaning "my display never goes stale on its own"; subclasses override it when they depend on outside state like installed ringtones.
