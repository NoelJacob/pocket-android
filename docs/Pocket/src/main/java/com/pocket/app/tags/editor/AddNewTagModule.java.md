# Pocket/src/main/java/com/pocket/app/tags/editor/AddNewTagModule.java
## What this is — the `add new tag "xyz"` row at the top of the tag editor's autocomplete list. It appears only while the user is typing something that is not already an existing tag; tapping it adds the typed text as a new tag. When the input is empty or matches a known tag, the row hides itself.
## How it fits — one of the plug-in sections managed by `TagModuleManager` inside `ItemsTaggingFragment`. The manager forwards every keystroke to `onTagInputTextChanged`, this module decides its own visibility via `setPreferredVisibility` (a request the parent adapter honors), and taps flow back through `getManager().addTag(this, tag)` so all other modules (chips, list, suggestions) stay in sync.
## Key pieces — `onTagInputTextChanged(text)`: stores the pending text; hides when empty or `containsTag` (case-insensitive known-tag check), otherwise formats the `ac_add_new_tag` string with the raw typed name and shows; WHY: the visibility rule is the entire feature. `onClick(v)`: adds `mPendingTag` through the manager; WHY: going through the manager (not editing chips directly) keeps validation and cross-module updates consistent. `load(callback)`: replays the pending text to set initial visibility, then reports loaded; WHY: participates in the manager's load-countdown without async work. `getView()`: the inflated `view_simple_title_divider_row` styled as a link; WHY: looks like an action, not a tag.
## Junior notes — `Phrase.from(...).put("name_of_tag", ...)` is the string-template call filling the `"xyz"` placeholder — `toString()` on the input strips the underline span the `EditText` (text field) carries, so keep that conversion. `onTagAdded`/`onTagRemoved` are intentionally empty: this row never reflects selection state, it only creates tags.
