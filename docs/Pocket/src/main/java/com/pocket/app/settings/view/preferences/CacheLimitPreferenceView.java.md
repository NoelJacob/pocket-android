# Pocket/src/main/java/com/pocket/app/settings/view/preferences/CacheLimitPreferenceView.java
## What this is — the offline-cache settings widget: a slider (seekbar) for the download storage limit plus text showing the current limit, roughly how many articles that holds, and how much space the cache uses now. Dragging the slider updates the labels live and reports the final value when the user lets go. It appears on the `CacheSettingsFragment` screen.
## How it fits — hosted inside the cache settings screen, which calls `setLimit()` to initialize the slider from the saved preference and `setItemOrder()` to describe the download priority ("newest"/"oldest") in the item-count sentence. Slider releases flow out through `OnCacheLimitChangedListener.onCacheLimitChanged(bytes)` so the fragment can persist them. It reads live usage from the `Assets` offline-cache service and must have `releaseResources()` called when the screen goes away.
## Key pieces — `mSeekbar` (`CacheLimitSeekbar`) + `setLimit()`/`getLimit()`: slider position in bytes, with `UNLIMITED = 0` as the sentinel; WHY: the whole widget is a visual editor for one byte-count setting. `setOnCacheLimitChangedListener` + the progress listener: refreshes both labels on every movement but only fires the callback when `isDragging` is false; WHY: avoids saving dozens of intermediate values mid-drag. `updateLimitToTextView` / `updateCacheDescriptionTextView` / `convertCacheSizeToItems`: format MB vs GB, build the "about N items" sentence via `Phrase` (a string-template library), and estimate items from average bytes-per-item minus a cache buffer, rounded down to fives; WHY: the estimate is deliberately fuzzy so users do not expect an exact count. Inner `CacheSizeListener`: observes `Assets` size changes and shows "currently adjusting" while trimming, nothing when within a set limit, or "currently using X" when unlimited; WHY: three states keep the user from worrying about transient trim activity. `releaseResources()`: unregisters the cache listener; WHY: otherwise the dead screen keeps receiving callbacks.
## Junior notes — `VisualMarginConstraintLayout` is just the base layout class handling Pocket's edge margins — no behavior to learn. `App.threads().runOrPostOnUiThread` is required because cache-size callbacks arrive on a background thread and Android views may only be touched on the main (UI) thread. Forgetting `releaseResources()` in the fragment's teardown is the leak to watch for.
