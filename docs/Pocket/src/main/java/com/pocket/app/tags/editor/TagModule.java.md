# Pocket/src/main/java/com/pocket/app/tags/editor/TagModule.java
## What this is — the abstract base class for every section of the tag editor (chip field, suggestions, recents, full list, add-new row, empty state). It defines the lifecycle every section follows — provide a view, load async data, react to typing, react to tags being added or removed — plus the visibility-request mechanism the parent adapter honors. It holds the manager, a context, and small helpers, nothing more.
## How it fits — `ItemsTaggingFragment` creates one subclass per section and hands them all to `TagModuleManager`, which calls `load()` on each at startup (counting down until all report back), broadcasts `onTagsLoaded` once the owned-tag set arrives, and forwards every typing/add/remove event to all modules except the originator. The adapter shows or hides each module's view based on `isPreferredVisible()`. New editor sections must extend this class — never bolt UI directly onto the fragment.
## Key pieces — `getView()`: the section's row view (may be null for `TagListModule`, which contributes adapter rows instead); WHY: gives the adapter something to show/hide per section. `load(callback)`: do async setup, then call `onTagModuleLoaded()` exactly once; WHY: the manager gates the whole screen on every module reporting in. `onTagInputTextChanged(text)` / `onTagAdded(tag)` / `onTagRemoved(tag)`: the three broadcasts; WHY: typing filters, adds/removes keep every section mirroring one shared selection. `setPreferredVisibility(visible)` + `isPreferredVisible()` + `VisibilityListener`: request (not command) to show/hide; WHY: the adapter owns placement and may combine conditions (e.g. sticky headers). `onTagsLoaded(allTags)` (default no-op) and `onPremiumStatusChanged()` (default no-op): optional hooks; WHY: only sections that care (list filtering, suggestions gating) override them. `app()` / `getContext()` / `getManager()`: protected accessors; WHY: subclasses never store their own copies.
## Junior notes — The visibility being a preference trips everyone up: calling `setPreferredVisibility(true)` does not set view visibility — it notifies the listener, and the adapter decides. Forgetting to call the load callback in a new module hangs the editor on its spinner forever, because the manager waits for every module. Keep modules dumb about each other; all cross-talk goes through the manager.
