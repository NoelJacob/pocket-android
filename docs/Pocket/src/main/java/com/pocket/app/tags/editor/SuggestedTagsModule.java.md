# Pocket/src/main/java/com/pocket/app/tags/editor/SuggestedTagsModule.java
## What this is — the Premium-only "suggested tags" chip row in the tag editor (single-item mode only). It fetches server-generated tag suggestions for the article's URL, shows them as tappable chips with a loading spinner and a tap-to-retry error state, and removes each chip as it is picked. Non-Premium users never see it.
## How it fits — created in `ItemsTaggingFragment.addSuggestedTagsModule` (skipped entirely in bulk mode) with the item's URL, and registered with `TagModuleManager`. `load()` kicks off `fetchSuggestedTags()`; chip taps call `getManager().addTag()` and remove the chip; the fragment reads `getSuggestTagsInitialCount()` at save time for analytics. `ChipLayout` (a flow layout of tappable chips) renders each suggestion via a `SuggestedTagView` adapter.
## Key pieces — `fetchSuggestedTags()`: bails immediately without Premium (`hasFeature(SUGGESTED_TAGS)`), otherwise shows spinner, hides chips/error, and queries the `V3Source` suggestions endpoint; WHY: the Premium gate is client-side so the row simply never loads for free users. Retry path (`mError` click → `mRetryStartedAt` + refetch, `MIN_RETRY_LOADING_TIME` 500ms minimum spinner): guarantees the spinner is perceptible on fast retries; WHY: an instant error→error flash reads as "tap did nothing". `onItemClick(parent, view, position)`: adds the tapped tag through the manager, removes that chip, emits on `mItemClicks` (an RxJava `PublishSubject`, a push stream observers subscribe to); WHY: manager routing keeps chips/list/suggestions in sync while the subject lets outsiders observe picks. `invalidateVisibility()` (on hierarchy change = when chips are added/removed): hides the section when no chips remain or while autocompleting; WHY: an empty suggestions box must collapse, not linger. `getTags()` / `getSuggestTagsInitialCount()`: live suggestions and the count at load for save-time analytics; WHY: "how many were offered" is logged even if the user picked none.
## Junior notes — RxJava (`Observable`, `PublishSubject`) here is just an event bus for chip taps — subscribe with `getItemClicks()`, do not poll `getTags()`. `mTagResponseJson` is kept only for error reports, not for logic — do not build features on it. The 5202 error code (`X_ERROR_SUGGESTED_TAGS_NO_TAGS`) means "server has no suggestions", which renders as hidden, not as an error.
