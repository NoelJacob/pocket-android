# Pocket/src/main/java/com/pocket/app/settings/view/preferences/Preference.java
## What this is — the abstract base class for every row in Pocket's custom Settings lists. Each subclass represents one row: it knows its view type for recycling, how to fill in a row view, whether it is enabled or tappable, how to refresh when outside state changes, and what happens on tap or long-press. It is both the data (the setting) and the row controller.
## How it fits — settings fragments (subclasses of `AbsPrefsFragment`) keep an ordered `List<Preference>` as their entire screen content. The fragment's `PrefAdapter` (the object turning list positions into visible rows) calls `getType()` to pick which layout to inflate or reuse, `applyToView()` to bind data into the recycled row, and forwards taps to `onClick()`/`onLongClick()`. Concrete rows are `ActionPreference`, `ToggleSwitchPreference`, `HeaderPreference`, `ImportantPreference`, and the cache-limit row; `PrefViewType` is the enum the adapter switches on.
## Key pieces — `PrefViewType` enum (`BANNER, HEADER, ACTION, TOGGLE, CACHE_LIMIT, IMPORTANT`): the recycling bucket; WHY: Android's list adapter reuses row views only within the same type, so each visual style needs an entry. `getType()`: declares the bucket; WHY: a wrong type means the wrong layout gets cast and the app crashes. `applyToView(view)`: fills the (possibly recycled) row; WHY: must set every visible field because the view may carry a previous row's state. `isEnabled()` vs `isClickable()`: enabled controls greyed-out appearance, clickable controls whether taps register; WHY: a row can be visible-but-dead (header) or greyed-but-present (unavailable setting). `update()`: re-read backing state, return true if the row needs redrawing; WHY: lets the fragment refresh only stale rows when returning to the screen. `SimplePreference`: a do-nothing row used as a banner placeholder; WHY: reserves a slot in the list without behavior.
## Junior notes — `BaseAdapter.getItemViewType()` is the Android framework method this `getType()` feeds — if you add a new row style you must add both the enum value and the adapter's layout mapping or recycling will mix layouts. `mSettings` (the owning fragment) is how rows trigger a list refresh (`onPreferenceChange(true)`) after they mutate a setting — the row never redraws itself directly.
