# Pocket/src/main/java/com/pocket/app/tags/StandaloneItemsTaggingActivity.java
## What this is — a variant of the tag-editor activity used when tagging is launched from outside the normal app flow (e.g. a share or widget entry point where Pocket is not already open). It behaves exactly like `ItemsTaggingActivity` except its window is transparent, it has no transition animation, and it opts out of the rotation-lock feature.
## How it fits — `ItemsTaggingActivity.newStartIntent(..., isStandalone=true)` targets this class instead of the base activity. `ItemsTaggingFragment.finish()` checks `getActivity() instanceof StandaloneItemsTaggingActivity` to also finish the activity when the editor closes. Everything else — fragment creation, login requirement, analytics view name — is inherited unchanged.
## Key pieces — `onCreate` + `onConfigurationChanged`: both re-apply a transparent window background; WHY: re-applying on rotation matters because the window background resets on config change and an opaque flash would show. `finish()` calling `overridePendingTransition(0, 0)`: suppresses the exit animation; WHY: a standalone popup should vanish, not slide like a normal screen. `supportsRotationLock()` returning false: disables the floating rotation-lock button on this screen; WHY: a transient transparent activity should not offer to pin orientation.
## Junior notes — "Standalone" here means "no Pocket task behind it", not "offline". If you are adding a new launch path from inside the app, use `isStandalone=false`; reserve `true` for external entry points. There is no layout or fragment code here by design — do not add any.
