# Pocket/src/main/java/com/pocket/app/settings/view/preferences/RingtonePreference.java
## What this is — the notification-sound settings row. It shows the current ringtone's name as its subtitle; tapping it opens the Android system sound picker, and the chosen sound's URI (its address string) is saved into a persisted `StringPreference` (a saved text setting). Picking "Silent" stores null.
## How it fits — declared in the notification settings fragment via a builder, rendered as an `ACTION` row. `onClick` launches the system picker with `startActivityForResult` (the old Android pattern: open another screen and get a result back in `onActivityResult`); when the user picks, `onActivityResult` saves the URI string and calls `onPreferenceChange(true)` so the list redraws. `update()` re-reads the pref in case it changed elsewhere, and `getSummary()` resolves the stored URI to a human name.
## Key pieces — `mPref` (`StringPreference`) + `mSelected`/`mSelectedUri`: the saved URI string and its parsed form; WHY: the string is what persists, the `Uri` is what the picker and player need. `onClick(view)`: fires `RingtoneManager.ACTION_RINGTONE_PICKER` filtered to notification sounds, pre-seeded with the current choice and offering Default + Silent; WHY: delegates the whole sound-browsing UI to the OS. `onActivityResult(requestCode, resultCode, data)`: ignores anything that is not our `REQUEST_CODE = 55` with `RESULT_OK`, then saves the picked URI; WHY: the guard clauses prevent other screens' results from corrupting this setting. `getSummary()`: returns the "silent" string for null, otherwise `RingtoneManager.getRingtone(...).getTitle(...)`; WHY: users read names, not URIs.
## Junior notes — `startActivityForResult`/`onActivityResult` is the legacy result API (new code uses the Activity Result contracts) — follow the existing pattern here rather than modernizing one row. `Ringtone.getTitle()` needs a valid context and can return odd names for missing files; the stored URI string surviving an uninstalled sound pack is expected, not a bug to "fix" with validation.
