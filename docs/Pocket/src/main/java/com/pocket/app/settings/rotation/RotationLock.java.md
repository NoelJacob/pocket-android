# Pocket/src/main/java/com/pocket/app/settings/rotation/RotationLock.java
## What this is — the single place that remembers and applies Pocket's in-app orientation lock. It stores the locked orientation in a persisted `IntPreference` (a saved integer setting that survives app restarts, here `AppPrefs.ORIENTATION`) and applies it to whatever `Activity` (one full-screen app page) is showing. Unlocking returns the app to sensor-driven rotation.
## How it fits — constructed once by Hilt DI (constructor params provided automatically, here `AppPrefs`) as a `@Singleton` (one shared instance app-wide). `RotationLockComponents` calls `setLocked()` when the user taps the lock button or disables the feature in settings, and calls `applyCurrentOrientation()` when activities restart so the lock persists across screens. The saved value also drives `isLocked()` checks everywhere else.
## Key pieces — `RotationLock(AppPrefs)`: grabs the `ORIENTATION` int preference; WHY: the lock must survive process death, so it lives in prefs not memory. `isLocked()`: returns true unless the saved value is `UNSPECIFIED` or `SENSOR` (both mean "follow the device"); WHY: the rest of the feature keys off this one predicate. `setLocked(lock, activity)`: on lock, snapshots the device's current full orientation (portrait vs reverse-portrait vs landscape vs reverse-landscape) and saves it; on unlock, saves `UNSPECIFIED` on Android P+ (needed for the OS lock UI to appear) or `SENSOR` below P; WHY: encodes the platform quirk in one spot. `applyCurrentOrientation(activity)`: calls `activity.setRequestedOrientation(savedValue)`; WHY: re-applies the lock to each new screen. `getFullOrientation(rotation, orientation)`: maps display rotation + portrait/landscape config to one of the four exact `SCREEN_ORIENTATION_*` constants; WHY: locking "current" must include upside-down variants or the screen would flip.
## Junior notes — `Activity.setRequestedOrientation()` is an Android framework call that pins that screen's rotation; `ActivityInfo.SCREEN_ORIENTATION_*` are the constants it takes. The `TODO research` comment on `UNSPECIFIED` vs `SENSOR` is a real behavior question — do not "clean it up" by unifying them without testing the Android P system rotation prompt. This class never shows UI itself; it only changes state that activities and the lock button react to.
