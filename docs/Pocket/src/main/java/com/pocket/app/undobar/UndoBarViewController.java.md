# Pocket/src/main/java/com/pocket/app/undobar/UndoBarViewController.java
## What this is — the overlay view behind the undo bar: it inflates the bar layout (message + Undo button + hidden confirmation text), attaches it as a floating window on the current activity, fades it in, swaps to a confirmation state when Undo is tapped, and detaches everything on timeout. One controller instance spans multiple activities — it keeps one `ActivityInstance` (the per-screen window attachment) per visited activity. The `TODO consider changing to a snack bar` note is aspirational; this custom window logic is what runs today.
## How it fits — created and driven by `UndoBar.showUndoUi()`, which calls `setListeners` (what to run on finish vs on undo-tap), then `attach`/`detach` as the `ActivityMonitor` reports navigation, and `startTimeout` to begin the 5-second clock. Tapping the button fires the `Undo` callback (which syncs the inverse action) and extends display by the 2-second confirmation period; touching the bar without tapping extends the full 5 seconds. `finish()` detaches all windows and fires `OnFinished` (which releases the sync-engine item hold).
## Key pieces — `attach(activity)` / `detach(activity)`: wrap the inflated view in an `ActivityInstance` (a `WindowManager` overlay with `PixelFormat` translucency) and add/remove it, retrying once next loop if the window is not active yet; WHY: the bar must survive activity switches without belonging to any one screen. `startTimeout()` + `extendHide(duration)` + `mDetachRunnable`/`mFadeoutRunnable`: schedule detach at N ms and fade-out 333 ms earlier, cancelling prior schedules each time; WHY: every touch or tap resets a single shared clock. `onClick(view)`: one-shot guard (`mHasClicked`/`mIsFinished`), fires `mUndo`, flips all instances to confirmation, extends by `CONFIRMATION_DISPLAY_DURATION`; WHY: undo applies once even under double-taps, then the user sees proof it worked. `onTouch`: extends the full duration on down/move/up unless already undone; WHY: interacting with the bar means "I am reading this, do not vanish". `inflate(context)`: binds message/confirmation texts and wires button click + touch, with a Kindle Fire text-size/padding special case; WHY: all per-screen view state is rebuilt fresh per activity. `finish()`: idempotent teardown removing callbacks and detaching all instances; WHY: safe to call from timeout, hide-all, and logout paths.
## Junior notes — This adds a raw window via `WindowManager`, not a view in the activity layout — that is why it can overlay any screen but also why leaks (missing `detach`) show as ghost bars over other apps' activities. `mHasClicked` vs `mIsFinished` are different: clicked means "undo sent, showing confirmation", finished means "windows gone, callbacks fired" — check the right one. Alpha animation uses wall-clock `mStartTime` so re-attaching mid-fade-in resumes at the right opacity instead of restarting.
