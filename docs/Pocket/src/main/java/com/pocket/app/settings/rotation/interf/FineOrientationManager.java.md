# Pocket/src/main/java/com/pocket/app/settings/rotation/interf/FineOrientationManager.java
## What this is — a tiny interface for the sensor that notices small orientation changes while locked. It lets the coordinator mark the current position as "known", turn listening on or off, and get a callback when the device moves enough to count as a new rotation. It has no implementation here — it only defines the contract.
## How it fits — `RotationLockComponents` receives a `FineOrientationManager` and calls `setEnabled(true)` only while the app is locked and in the foreground, `markCurrentOrientation()` after showing or toggling so the same position does not re-trigger, and listens via `OnNewRotationListener` to re-show the unlock button. The concrete sensor class lives elsewhere; this file keeps the coordinator testable and decoupled from hardware.
## Key pieces — `setEnabled(enabled)`: start/stop sensor listening; WHY: sensors cost battery, so listening is scoped to locked-and-visible. `markCurrentOrientation()`: snapshot the current angle as baseline; WHY: prevents the just-locked position from immediately firing a "new rotation". `setOnNewRotationListener(listener)` + `OnNewRotationListener.onNewRotation()`: the single callback for "device moved enough"; WHY: the coordinator only cares that it happened, not the raw degrees.
## Junior notes — "Fine" here means finer than Android's coarse `onConfigurationChanged` (which only fires after the screen actually rotated); this listens to the raw orientation sensor so it can offer "unlock?" before anything visibly flips. Interfaces like this are the seam where you would plug in a fake in tests.
