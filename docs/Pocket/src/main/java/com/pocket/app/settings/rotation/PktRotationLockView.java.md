# Pocket/src/main/java/com/pocket/app/settings/rotation/PktRotationLockView.java
## What this is — the floating lock/unlock button the user sees when the device rotates. It shows a small lock icon for about 4 seconds after a rotation is detected, then fades itself out. Tapping it toggles the in-app orientation lock and fires an analytics event.
## How it fits — created in layout/activity code as the `RotationLockView` passed into `RotationLockComponents`. `RotationLockComponents` calls `show(checked)` / `hide()` on it when rotation events happen, and registers an `OnClick` handler via `setOnToggleClick` that locks or unlocks via the `RotationLock` class. It logs a `Pv` analytics event (section `ROTATION_LOCK`, `ENABLED`/`DISABLED`) on every tap.
## Key pieces — `PktRotationLockView(...)` constructors plus `init()`: inflate `view_rotation_lock` layout, style the toggle with a translucent box background and tinted rotation icon; WHY: the single entry point that turns the raw `FrameLayout` (a container view that stacks children) into the styled button. `show(checked)`: makes the view visible, sets the toggle state, and schedules auto-fade; WHY: this is what the user actually perceives as "the lock prompt appeared". `hide()`: sets visibility to `GONE` (removed from layout entirely); WHY: keeps it off screen when not needed. `setOnToggleClick(OnClick)`: wires the toggle tap to the caller and reports analytics; WHY: separates the visual button from the lock decision logic. `scheduleFadeOut(delay)` + inner `FadeOut` runnable: runs a 620ms alpha fade to transparent then hides; WHY: the prompt must disappear on its own so it never blocks reading.
## Junior notes — `FrameLayout` here just means "a view container inflated from XML"; `CheckableImageView` is an image that also holds a checked/unchecked state like a checkbox. Touching anywhere on the view reschedules the fade (`setOnTouchListener`), so tapping without hitting the icon still keeps it alive briefly. Analytics uses `Interaction.on(toggle).context` to capture which UI element was tapped — you do not need to build that context by hand.
