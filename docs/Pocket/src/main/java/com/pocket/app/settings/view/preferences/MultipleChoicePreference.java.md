# Pocket/src/main/java/com/pocket/app/settings/view/preferences/MultipleChoicePreference.java
## What this is — a settings row for picking one option out of a short list backed by a saved integer (an `IntPreference`, a persisted number setting). The row shows the current choice as its subtitle; tapping it opens a single-choice dialog, and picking an item saves the new index. The constructor is deprecated — use `PreferenceViews.newMultipleChoiceBuilder()` instead.
## How it fits — settings fragments declare one per multi-way setting (e.g. theme, list density), passing a `PrefHandler` (tiny get/set-selected-index adapter over the real pref) and a `SparseArray` of choice labels that doubles as the summary map. The fragment adapter renders it as an `ACTION` row; `onClick` opens the `AlertDialog` (a standard Android popup list), and `onItemSelected` persists via the handler then notifies the fragment with `onPreferenceChange(true)` so the list redraws.
## Key pieces — `PrefHandler.getSelected()/setSelected(index)`: the storage seam; WHY: lets one UI class work over any int-backed setting. `mChoices` built from the summary array: the dialog items; WHY: guarantees the row subtitle and dialog list can never disagree. `onClick(view)`: builds the single-choice dialog with the current selection checked plus a Cancel button; WHY: the entire user-visible flow lives here. `onItemSelected(view, newValue, dialog)`: asks the `OnSelectedItemChangedListener` for veto first, then saves, notifies the fragment, and fires `onItemSelectionChanged`; WHY: the two-phase callback lets callers block a change (return false) separately from reacting after it. `getSummary()`: returns `summary.get(mSelected)`; WHY: the subtitle always mirrors the saved index. `update()`: re-reads the pref and reports whether the cached index changed; WHY: lets the adapter refresh the row if the setting changed elsewhere.
