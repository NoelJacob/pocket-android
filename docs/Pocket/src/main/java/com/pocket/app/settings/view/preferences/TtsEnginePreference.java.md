# Pocket/src/main/java/com/pocket/app/settings/view/preferences/TtsEnginePreference.java
## What this is — the "Text-to-speech engine" row in Listen settings. Its subtitle shows the currently selected TTS engine's name (the system service that reads articles aloud); tapping it opens the engine picker, and the subtitle refreshes to whatever the user chose. It shows a fallback/unavailable text when no engine or feature is available.
## How it fits — added to the Listen/TTS settings fragment like any other action row and rendered as `PrefViewType.ACTION`. `onClick` delegates entirely to `TtsEngines.showPicker()` (a helper in the SDK layer that lists installed engines and persists the choice); the `OnTtsEngineSelectedListener` callback calls `update()` so a real change redraws the row. The fragment also calls `update()` when returning to the screen, which rebuilds the `TtsEngines` helper to pick up engines installed while the user was away.
## Key pieces — `mEngines` (`TtsEngines`) + `mSelected` (engine label string): the lookup helper and the cached display name; WHY: caching the label lets `update()` detect a change with a simple string compare. `onClick(view)`: opens the picker, refreshes on selection, ignores cancellation; WHY: all persistence lives in `TtsEngines`, this row is only a display. `update()`: constructs a fresh `TtsEngines`, compares the preferred engine label, returns true if different; WHY: the fresh instance is how newly installed engines become visible. `getSummary()`: returns the engine label, the "no engine" fallback string, or the "unavailable" string when the row is disabled; WHY: three states map to three user situations (chosen, none, feature off).
## Junior notes — TTS engines are other apps/services on the device (e.g. Google's) — the picker lists what is installed, so an empty list on an emulator is normal. `isClickable()` is always true; availability gating comes from the `EnabledCondition` passed at construction, not from this class.
