# Pocket/src/main/java/com/pocket/app/settings/view/preferences/ToggleSwitchPreference.java
## What this is — a settings row with an on/off switch, bound to a persisted boolean. Tapping the row flips the switch, saves the new value, and refreshes the subtitle (which can differ between on, off, and unavailable states). An optional listener can veto the flip before it saves.
## How it fits — built via `PreferenceViews.newToggleSwitchBuilder()` in settings fragments, passing either a `BooleanPreference` or a custom `PrefHandler` get/set adapter. The fragment adapter renders it as `PrefViewType.TOGGLE` (a `SettingsSwitchView` with the toggle visible). `onClick` handles the whole tap-to-save flow and ends with `mSettings.onPreferenceChange(true)` so the list redraws; `update()` lets the fragment pull external changes into the cached `isChecked` flag.
## Key pieces — `PrefHandler.get()/set(value)`: the storage seam; WHY: the row works over any boolean source, not just prefs. `OnChangeListener.onChange(view, nowEnabled)` returning boolean + `afterChange(nowEnabled)`: veto hook then post-save hook; WHY: callers can block the flip (return false, e.g. upsell or confirm dialog) separately from reacting to it. `onClick(v)`: computes `!isChecked`, asks the veto, then saves, updates the cache, fires `afterChange`, and notifies the fragment; WHY: the ordering means a vetoed tap changes nothing visible. `getSummary()` / `applyToView(layout)`: pick the checked/default/unavailable subtitle and bind title + subtitle + `checked && enabled` into the row; WHY: a disabled row shows as off regardless of the saved value. `update()`: re-reads the pref, returns true if the row needs redrawing; WHY: covers changes made outside this row.
## Junior notes — The cached `isChecked` field is why `update()` exists: if something else flips the pref (e.g. a server-driven change), the row shows stale state until the fragment calls `update()`. `isClickable()` is always true here — greying out is controlled solely by the `EnabledCondition`, not by clickability.
