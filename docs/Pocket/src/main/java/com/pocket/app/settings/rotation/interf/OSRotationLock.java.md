# Pocket/src/main/java/com/pocket/app/settings/rotation/interf/OSRotationLock.java
## What this is — a three-method interface representing the phone's own system rotation lock (the toggle in Quick Settings). It can start and stop observing the system setting and report whether the OS lock is currently on. Like the other `interf` types, it defines a contract; the real Android-settings lookup lives in an implementation elsewhere.
## How it fits — `RotationLockComponents` calls `startObserving()` on activity resume and `stopObserving()` on pause, and checks `isLocked()` inside `isLockingAllowed()` before ever showing Pocket's in-app lock button. If the OS lock is on, Pocket's button stays hidden because the app cannot override the system. If the user turns the OS lock on mid-session, the observer lets the coordinator yield to the system.
## Key pieces — `startObserving()`: begin watching the OS setting, typically only while the screen is visible; WHY: avoids leaking a system observer. `stopObserving()`: stop watching; WHY: paired cleanup for the above. `isLocked()`: current OS lock state; WHY: the single predicate that disables Pocket's competing feature.
## Junior notes — Do not confuse this with `RotationLock` (Pocket's in-app lock) — this one is read-only visibility into what the operating system is doing. The start/stop pairing mirrors the Android activity lifecycle (visible = observing, hidden = not), a pattern you will see for every sensor or system listener.
