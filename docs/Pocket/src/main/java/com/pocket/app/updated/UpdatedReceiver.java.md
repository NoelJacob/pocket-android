# Pocket/src/main/java/com/pocket/app/updated/UpdatedReceiver.java
## What this is — the manifest-registered broadcast receiver (an Android component the OS wakes up when a matching system event fires) that hears the system tell us our own app was just updated. Its whole job is one line: forward that signal to `versioning().onAppUpdateReceiver()` so stored version state rolls forward. It ignores every other broadcast, including untrusted extras from outside apps.
## How it fits — Android delivers `ACTION_MY_PACKAGE_REPLACED` (the "your APK was just swapped" broadcast) to this exported receiver after an upgrade install. `App.from(context).versioning()` is the app's version tracker; its `onAppUpdateReceiver()` records the new version, which is what later makes `Versioning.isUpgrade()` true and triggers `UpdateAnalytics`. Without this receiver, the app would never notice it had been upgraded.
## Key pieces — `onReceive(context, intent)`: action check first, then the single `versioning()` call; WHY: the guard is both a correctness filter (only our own replacement matters) and a security boundary (exported receivers can be pinged by anyone). The WARNING comment about untrustworthy extras; WHY: reminds future editors never to read data from this intent — the action alone is the signal.
## Junior notes — "Exported" means any app on the device can send intents to this receiver, hence the strict action check — do not add extra-handling without validating the sender. `App.from(context)` is the cast from a generic context to the Pocket application object; it works here because the receiver runs inside our own process. This receiver does no UI and starts no activity; upgrade UI (if any) reacts to version state later, not here.
