# Pocket/src/main/java/com/pocket/app/settings/rotation/interf/RotationLockView.java
## What this is — the interface for the floating rotation-lock toggle button. It can register a tap handler, show itself in a checked (locked) or unchecked state, and hide itself. The real view is `PktRotationLockView`; this contract is what the coordinator programs against.
## How it fits — `RotationLockComponents` holds a `RotationLockView`, calls `show(rotationLock.isLocked())` whenever a rotation or sensor event says the prompt should appear, `hide()` on restart/destroy and after fade-out, and supplies the lock/unlock behavior once via `setOnToggleClick`. The `OnClick.onClick(checked)` boolean tells the coordinator the button's new state so it can call `RotationLock.setLocked(checked, activity)`.
## Key pieces — `setOnToggleClick(OnClick)`: one-shot wiring of tap behavior; WHY: keeps visual code (`PktRotationLockView`) free of lock logic. `show(checked)`: display the prompt reflecting current lock state; WHY: the same button doubles as "tap to lock" and "tap to unlock". `hide()`: remove the prompt; WHY: explicit dismissal for lifecycle and fade-out paths.
## Junior notes — The nested `OnClick` interface passing a `boolean checked` is not Android's `View.OnClickListener` — it already resolves the toggle state for you, so the handler does not need to read the view. Keeping this interface small means tests can fake the button with three trivial methods.
