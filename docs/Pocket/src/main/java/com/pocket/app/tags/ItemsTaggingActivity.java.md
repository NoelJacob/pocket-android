# Pocket/src/main/java/com/pocket/app/tags/ItemsTaggingActivity.java
## What this is — a thin full-screen host for the tag editor. It shows `ItemsTaggingFragment` (the real UI: chips, suggestions, tag list, save button) either as its content fragment or as a dialog, depending on the device form factor. It requires login. All user-visible behavior lives in the fragment; this activity is just navigation plumbing.
## How it fits — launched from anywhere via `startActivity(context, standalone, items, addOnly, cxts)` or by building an intent with `newStartIntent(...)`, which parcels (serializes for inter-screen transport) the item list (reduced to identities to avoid oversized parcels) plus analytics contexts. `onCreate` unpacks the intent back into `ItemsTaggingFragment.newInstance(...)` and shows it with `setContentFragment` on phones or `addFragmentAsDialog` on large-screen/dialog-mode devices. `ItemsTaggingFragment.show()` picks this activity as the fallback when dialog mode is not appropriate.
## Key pieces — `startActivity(...)` / `newStartIntent(...)`: choose `ItemsTaggingActivity` vs `StandaloneItemsTaggingActivity` by the `isStandalone` flag and pack items + contexts + `addOnly`; WHY: one static funnel so callers never hand-build the parcel extras. `onCreate(savedInstanceState)`: on first creation only, rebuild the fragment from intent extras and place it; on restore (`savedInstanceState != null`) do nothing because the framework re-attaches the fragment itself; WHY: re-adding on restore would stack a duplicate editor. `getActionViewName()` returning `CxtView.EDIT_TAGS`: tags every analytics event on this screen; WHY: one override classifies the whole flow. `getAccessType()` returning `REQUIRES_LOGIN`: blocks logged-out access; WHY: tagging is meaningless without an account.
## Junior notes — An `Activity` here is one full-screen page; a `Fragment` is a reusable UI piece inside one — this activity exists only because some form factors need the editor as a separate page rather than a popup. `copyAndReduceItemsForParcel` keeps only the first item's full state to dodge `TransactionTooLargeException` (Android's hard limit on inter-screen data); the fragment re-resolves the rest from local sync. Never add editor UI here — it belongs in `ItemsTaggingFragment` or the `tags/editor` modules.
